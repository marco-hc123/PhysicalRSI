# 最新实验结论（2026-11-02）

## 1. 分类任务：换 GPT 后输出更短，任务优势尚不能归因于模型

详细数据：[group-results.csv](../experiments/system1_gpt/group-results.csv)、[逐回合结果](../experiments/system1_gpt/episode-results.csv)。

普通分类平均 total Token 由 12,604 降至 11,661.6；语言分类由 12,332.4 降至 11,719.4。输入接近，下降主要来自输出缩短。本轮没有改变技能目录。

两模型在对应 10 个回合选择同一技能与操作。初始相机图像并非逐像素一致，且每组仅 5 个布局，不能据成功数与 Score 的变化断言 GPT 高层决策更优。历史千问与 GPT 的缓存口径及推理设置也不同。

本轮参考配置每回合一次高层规划，随后由已有本地 code/VLA 执行。这个观察不能推广为所有任务都只需一次 API 调用，也没有把本地 GPU 计算算作语言 Token。

## 2. System 2：生成用量减少，验证成绩没有提升

同一份历史候选生成请求的 system/user 内容保持一致；模型、端点、鉴权和必要兼容参数更换。历史千问 input/output/total 为 3,831 / 22,532 / 26,363；GPT 为 3,138 / 2,338 / 5,476。

GPT 生成一个候选并通过接口门禁，在普通分类的 5 个匹配布局上重新验证父策略和候选；两者均 0/5、平均 Score 0。原选择器返回 `retain_parent`。不能据一个候选推广为 GPT 普遍无效。

GPT 候选改用篮子 dims 计算入篮范围，但这只是源码结构差异，不等于物理判定已正确或任务完成。历史两轮千问候选和手工边界诊断仍属于原实验。

|---|---:|---:|
| 历史千问正式两轮 | 2 | 51,070 |

累计行包含前两行，不应再次求和。System 2 Token 是候选生成的语言模型用量，不是每个机器人回合都产生的用量。欠费停机恢复没有新增模型请求。

## 4. 当前限制

两组 GPT 补测都属于小样本验证。跨项目 A/B 对照不是完全公平的等条件实验。System 2 未新增第二个 GPT 候选或独立 20 布局验收。完整分母、中断记录、缓存与推理字段见每项实验的详细报告。
