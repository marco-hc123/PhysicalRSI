## 1. 我们要回答的研究问题

研究目标有两层：先复现 PhysicalRSI 的有限范围机器人仿真与自改进流程，再依据项目 A（GPT-as-Policy）的公开说明和结果，结合 PhysicalRSI 实测，解释两者为什么呈现很大的 Token 差异，以及这样的差异是否意味着整任务更快或效果更好。

本研究没有重新部署或运行项目 A。跨项目对照是公开记录与自身实测的条件性描述，不能写成同模型、同任务条件、同成功质量下的因果实验。项目 A 是他人的成果，不属于本次复现成绩。

目前最稳妥的结论是：PhysicalRSI 在本次分类配置中，每回合一次高层模型选择技能，之后由本地代码或 VLA 执行动作；这能解释语言交互开销为什么小。目录精简又能降低单次输入，但它是自身消融。低 Token 没有自动带来更高成功率；正式 System 2 和新模型补测都没有测得验证成绩改善。缺少 A 的完整墙钟，仍不能给出跨项目加速倍数。

## 2. 两项目在何处调用语言模型

项目 A 的公开机制中，语言模型参与较细粒度的动作段生成，并可能结合 VLA 控制。公开文件报告了动作段数量和聚合 Token，但动作段不是已经核实的 HTTP 请求次数，缺少的 HTTP 数不能自行补齐。

PhysicalRSI 的 System 1 接收任务说明、图像、可用技能及 memory 等信息，先决定使用哪个 composition 和 operations，再交给本地技能执行。机器人控制过程中仍然有反馈与 GPU 计算；只是这些本地计算不计入语言模型 Token。四条被测路线分别为固定 pi05、固定 sparse-memory VLA、固定 code skill，以及由高层 Agent 选路的组合。

System 2 是跨回合的改进流程：开发证据 → 候选代码与 memory → 接口门禁 → 父/候选匹配验证 → 选择与提交或保留父策略。它不等于每个机器人控制步都重新请求大模型，也没有在本研究中训练 VLA 权重。System 2 能生成并执行候选，不代表候选一定有性能收益。

RoboDojo 提供任务、布局、机器人接口与评分；Isaac Sim 提供物理与 RGB 渲染；cuRobo 参与运动规划；预训练 VLA 或代码技能实际输出控制动作。部署、渲染通过、规划可行、执行无异常和任务成功是不同层次的验证。

## 3. 复现版本、边界与证据层级

主要原生实验基于 PhysicalRSI `90b322a3a362aad14125f36d8ed080ca31daaea6`，但还包含冻结集成层及已记录的适配，不能把全部输出称为干净上游直接运行。每批 `protocol.json`、来源指纹、依赖版本和布局哈希才是具体复跑依据。早期 CPU 机制实验来自 `3c8cf7f`，只用于解释调度，不与新版原生结果混为同一实现。

原生路径使用 ARX X5、RoboDojo、Isaac Sim 5.1、RGB 输入及预训练技能。主要执行环境为单张 L20，Ubuntu 22.04、Python 3.11、PyTorch 2.7.0+cu128；详细条件见 [冻结协议](../../experiments/history/protocol_freeze/protocol.json) 与环境清单。H100 上做过策略依赖与兼容性检查，不能将其解释为 H100 已完成相同 RGB 原生仿真。

证据分为：静态代码/提示词审计；CPU 代理与计量 fixture；真实固定输入 API；原生机器人任务；System 2 生成与选择；独立验收与机制诊断。它们回答不同问题，不合并成一个“总成功率”。目录、ZIP、副本、逻辑回合、实际原生执行及失败启动也不相互替代。

## 4. 前期实验怎样帮助解释 Token

### 4.1 CPU、调度和计量工具

早期检查了 28 组调度配置与 6,922 个环境 chunk，验证高层规划次数怎样随 horizon、间隔和重置变化。512 个 CPU 代理控制回合中，逐步反馈与本地闭环组各 128/128，每四步反馈 110/128，开环 50/128。这里是手写代理、合成扰动，不是机器人成功率，也不是模型生成技能。

22 项计量测试和 72 行理论摊销计算用于检查账目与假设；其中 fixture Token 是人工设定值，不计入真实 API 用量。它们支持“减少语言调用并不等于取消控制反馈”这一机制理解，不证明原生机器人提升。[数据与脚本](../../experiments/mechanism_audit/README.md)

### 4.2 80 次与 120 次固定输入 API

80 次是三种提示契约的探索，覆盖相同合成输入的 projected/unprojected 对照。初始 22-operation 条件存在无效 composition 或 operations 类型错误，不能把 HTTP 200 当作可执行成功。修正 schema 后的 30 次请求为 5 个合成输入 × 2 条件 × 3 次；它与前面失败记录一起保留。

后续 120 次为 20 个新合成场景 × 2 条件 × 3 次，不是 120 个机器人布局。原始请求、供应商响应、元数据和 calls 表复核结果：

| 指标 | unprojected | projected | 均值比值对应降幅 |
|---|---:|---:|---:|
| 平均 input Token | 27,437.3 | 8,969.3 | 67.31% |
| 平均 total Token | 27,598.92 | 9,144.37 | 66.87% |
| 平均 HTTP 时间 / s | 14.4324 | 9.8643 | 31.65% |

120/120 HTTP、JSON 与定义的输出契约检查通过，标签一致性也通过；这些标签是实验作者设定的合成目标，不能视为真实机器人任务成功。供应商时段、缓存和重复效应尚未隔离。[原件、协议及复算](../../experiments/fixed_input_api/README.md)

### 4.3 原生目录精简消融

general_pickup 的 30 个案例槽中，两条件各 15，实际完成 native 为 projected 15、unprojected 14；另 1 个基础设施失败单列。按全部 15 个尝试的语言账目，平均输入 58,336.8 → 11,550.8，下降 80.20%；total 合计 888,970 → 186,568，下降 79.01%。记录的成功数分别为 unprojected 6/15、projected 5/15，没有证明成功率提高。[逐例表](../../experiments/history/catalogue_ablation/cases.csv)

这里的约 80% 是 PhysicalRSI 自身目录消融，不能拿来宣称两个项目之间节省了 80%。约 67% 则属于前面的合成 API 条件，也不能覆盖原生消融。

## 5. 原生任务效果说明了什么

冻结参考矩阵是两个分类任务 × 四条路线 × 每组 5 个布局，共 40 个正式回合；早期布局 0–4 的 Agent 组与冻结布局 5–9 组分开记录。

| 任务 | 固定 pi05 | sparse-memory | 固定 code | Qwen Agent |
|---|---:|---:|---:|---:|
| classify_objects | 0/5 | 0/5 | 2/5 | 1/5 |
| classify_objects_by_language | 0/5 | 0/5 | 1/5 | 1/5 |

成功由原生 success 字段决定；部分得分采用归一化 0–1，展示 Score 时可乘 100，但必须注明。固定技能的高层语言 Token 为 0，仍然消耗本地推理和仿真时间，不代表整任务没有计算成本。[参考矩阵与分母](../EVIDENCE_INDEX.md)

三项有限扩展任务每项 5 个正式案例：stack_bowls 1/5、部分得分 0.20；cover_blocks 3/5、0.64；insert_tubes 4/5、0.88。这说明系统在选定任务中能够产生非零原生表现，不能推广为 RoboDojo 全集成绩或与官方排行榜完全匹配。早期 general_pickup、开发 smoke、诊断回合和这些正式组不重复累计。

## 6. 跨项目 Token 与缓存应怎样比较

统一账目：`total = input + output`。缓存命中输入是 input 的子集；reasoning 如果已包含在 output，不能再相加。`input - cached_input + output` 可作为去缓存描述指标，但没有乘各模型单价，不能直接叫费用。

对应两个分类任务、各 A 方法和 B 历史 Qwen Agent 的每组样本均为 5。公开 A/B total 均值描述比值约 888–3,050，去缓存指标比值约 27.59–75.88。A 的 input 中约 97%–98% 为缓存命中，因此原始 total 差距和新计算量差距不是一回事。[复核表](../../reports/evidence/tables/matched_comparison_recomputed.csv)

公开 A 的普通分类 mix/gpt 成功分别为 3/5、5/5，语言分类为 1/5、2/5；B 历史 Qwen Agent 两任务均 1/5。模型、推理配置、任务条件、布局与成功质量存在差异。公开全站分母中还有不完整尝试，不能只挑成本或只挑成功结果。不同聚合范围必须注明。

B 的直接机制证据是：正式分类每例记录一次实际高层 HTTP，后续本地执行；提示词主要由 operation program、memory、目录与观测组成，图像和文本编码也会影响单次 input。A 有更多动作段与反复语言交互的机制，但实际 HTTP 次数和完整墙钟仍未知。当前无法量化架构、模型、缓存、任务难度各自的因果贡献。

## 7. 为什么 Token 下降不必等比例加速

必须区分仿真物理时长、API 请求时间、reset-to-result、包含服务启动与加载的完整进程墙钟。局部计时区间可能重叠，不能把所有分项直接相加；未覆盖区间保留为 unassigned。

历史 Qwen Agent 的普通/语言分类 reset-to-result 平均约 236.53 / 214.76 秒，API 平均约 17.40 / 12.27 秒。本地策略、原生控制、渲染、通信及其他区间占据余下时间。因此减少一次提示词或输出的效果会被其他耗时稀释。

针对性冷启动/连续运行是 3 对小样本，约 231.92 / 236.71 秒，未观察到连续运行更快；它不是严格清空所有缓存的启动实验。A 的完整墙钟缺失，不能据物理视频时长或 API 总时长声称跨项目加速多少倍。

## 8. System 2：已完成的流程和未实现的收益

历史正式两轮都完成了候选生成、接口验证、父/候选匹配验证和选择；每轮父与候选各 5 例，均 0/5、平均得分 0，选择器均 retain_parent。最终保留 pi05，不能把后续人工诊断修订当作系统自己采纳的改善。

正式两次候选生成合计 51,070 total Token。接入失败和早期尝试也保留，不能只报成功提案成本。计量工具、CPU 门禁、API-only 生成、已复用的开发证据和真实 native 验证分账，不把每个逻辑阶段都当作一次新执行。

独立最终验收评估的是最终保留的固定 pi05：两个任务各 10 个独立布局，均 0/10；不是整套 Agent 的最终成绩。状态恢复另完成一致性、损坏检测、拒绝候选阻断、幂等恢复等软件检查，并有 baseline/restored 各 1 次 native smoke，均 0 分；这证明了特定恢复链，不证明全盘丢失或主机灾难恢复，也不属于新的独立性能验收。

## 9. 负结果定位到了哪些机制问题

机制对照共 9 个诊断启动：5 个自然完成但得分 0，4 个异常结束，后者评分未知。另有 24 个离线规划检查，不能算 24 个机器人回合。

1. 原候选的入篮边界过宽，可能在最初就认定物体已完成，出现没有 approach/gripper 调用的现象。修正边界后动作增加，但得分仍为 0。
2. 发起动作后可能在运动规划阶段返回 no-path；抬高目标能改善部分离线可行性，不等于完成抓取或放置。
3. 规划轨迹过密影响执行预算；简单抽稀可能触发动作跟踪保护，不能把点数减少当作速度提升或成功。
4. 动态类别映射修订消除 KeyError 后，仍可能存在执行失败。
5. 候选生成获得的 current_code、逐步 RPC 错误与执行失败反馈不完整，可能限制候选对真实瓶颈的修复能力；这是下一轮待干预的问题，不能据此宣称已经修好。

[诊断报告](../../experiments/history/system2_diagnostics/report-zh.txt) 与 [人工对照逐例表](../../experiments/history/system2_diagnostics/verified-control-results.csv) 共同使用。附带 13 段历史展示视频，其中重点呈现一个分类成功例、一个跳过动作失败例及边界修订后动作增加但失败的对照，均不是 GPT 补测视频，也不是随机抽样。

## 10. 2026-11-02 模型替换补测

### 10.1 System 1：输入不变，输出变短，质量归因仍有限

保持任务、布局 5–9、技能目录和执行预算等，将高层更换为 `gpt-6.1-sol / medium`；两任务各新增 5 个原生回合。供应商、端点与兼容参数也变化，并非只改变一个因素。

| 任务 | 历史 Qwen → GPT 成功数 | Score（0–100） | 平均 total Token | API 时间变化 | reset-to-result 变化 |
|---|---|---|---|---:|---:|
| 普通分类 | 1/5 → 1/5 | 32 → 47 | 12,604 → 11,661.6（−7.48%） | −9.24% | −3.01% |
| 语言分类 | 1/5 → 2/5 | 30 → 46 | 12,332.4 → 11,719.4（−4.97%） | +35.09% | −1.26% |

两模型 10/10 对应回合选择相同 composition 与 operations；输入约 1.15 万，下降主要来自输出。相机 PNG 不逐像素一致、没有交错随机重复，所以不能把部分得分和成功数的差别归因于 GPT 做了更好的技能选择。普通分类旧组有缓存命中，新组为 0；去缓存指标反而增加，total 下降不等于同幅省费。

新增为 10 个正式原生回合、10 次正式高层 HTTP，另 1 次 smoke。逐回合 CSV 的另外 10 行是旧参考，不再算新执行。对公开 A 的更新描述比值为 total 约 960–3,209、去缓存指标约 27.59–79.84；A=Astra/xhigh 与 B=Sol/medium 仍不是等条件比较。[详细补测](../../experiments/system1_gpt/RESULTS_ZH.md)

### 10.2 System 2：生成更短，但新候选仍未提升

复用同一份历史生成 messages 和开发反馈，只生成 1 个 GPT 候选，不手工修候选。父策略与候选各完成 5 个匹配验证案例，均 0/5、得分 0；选择器 retain_parent。共 11 次原生启动，其中 1 次为基础设施中断，score/success 未知；它不算策略 0 分。复用的 10 个历史开发案例不算新执行，没有新增第二轮 GPT 候选或 20 布局独立最终验收。

对应一次生成：历史 Qwen 26,363 → GPT 5,476 total Token（−79.23%）。GPT input=3,138，output=2,338；其中 reasoning=512 已包含在 output，cache_write=3,135 不等于 cached hit（0）。历史/新请求记录耗时 361.79 / 33.86 秒；新计时含客户端与 SSH 转发，不是供应商纯 API 提速倍数，更不是机器人任务加速倍数。

候选 generation 账目与机器人 validation 账目分开。累计 5 次生成记录 411,352 total Token 包含历史两次正式生成和本次 1 次，不能与其子集再次相加。更省的生成没有转化为本轮可测任务收益。[详细补测](../../experiments/system2_gpt/RESULTS_ZH.md)

## 12. 如何使用这份仓库

先读本文与 [证据导航](../EVIDENCE_INDEX.md)，再按研究问题进入 CSV/JSON 和详细报告。历史长报告保留所有过程、失败、限制与场景说明；今天新增内容在两项 GPT 补测和整合说明中。没有要求汇报按执行流水账顺序讲，也没有在本次修改现有 PPT。

离线克隆后运行 `python tools/verify_results.py` 与 `python tools/verify_research_evidence.py`。第二个命令还支持本次新增证据的哈希、无损 JSONL 原件恢复校验与关键统计复算。两者都不调用模型、不启动仿真。权重、完整环境、全部观测和未选视频仍在原档案，本仓库不宣称是服务器完整镜像。
