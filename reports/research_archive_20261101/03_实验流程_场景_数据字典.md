# 实验流程、场景与数据字典

本文帮助没有原仓库的读者理解“每项输入从哪里来、怎样变成动作、最后怎样形成表格”。全部主题与结论的证据入口另见 `02_结论证据表.csv`。本资料不限定 PPT 页数。

## 一条真实 System 1 episode 的数据流

1. **任务与布局**：RoboDojo 根据任务名和布局文件放置机器人、桌面、目标/干扰物。布局标签用于原生评分；它不是默认向 Agent 提供的真值清单。`sources/scene_layouts/` 给出了所选演示的原始公共布局 JSON。
2. **观察**：模拟器产生 head/left-wrist/right-wrist 三路 RGB 和关节/末端状态，连同 instruction 形成 observation。参考阶段核验了初始指令与状态；同一布局运行的 RGB 仍可能不同。
3. **高层请求**：Agent 的 system 指令规定 composition/operations/rationale 输出格式。user context 传入任务、观测、技能能力、程序目录、已有 memory/计划。实际请求还包含图像。保存的 portable JSON 用文件名与 SHA 引用图像，不能把它误当实际线上 base64 payload 的完整字节数。
4. **模型返回**：供应商返回内容、usage、model alias、finish_reason 等；本地验证 composition 是否有效以及 operation 句柄是否存在。HTTP200 并不保证 plan contract 正确，也不保证机器人任务成功。
5. **本地技能运行**：选择 VLA 时加载发布权重并输出控制动作；选择 code 时运行已发布或独立候选程序，通过感知/规划/夹爪 primitive 与原生环境交互。一个远端高层计划后可以执行很多控制步。
6. **原生结果**：RoboDojo 的 reward/score、控制步数、终止原因和视频写入记录。完整评分要满足原生任务条件；“程序返回了”或“夹爪移动了”都不是成功的替代定义。
7. **计量与导出**：从 episode events、实际请求/响应、单调时间和 native result 对齐，生成逐例表，再按任务、路线、用途和结果分组。不跨角色混合分母。

## 一轮 System 2 的数据流

开发布局 → 两种 VLA 的开发执行/反馈 → proposer 的 request/response → 原始候选代码及 memory_rules → CPU/隔离契约检查 → 父策略与候选的原生配对验证 → 官方 selector → survivor、lineage、content-addressed snapshot → 后续独立测试/恢复。

本次两轮都 retain_parent。下一轮的 parent 因而仍是保留的 pi05；它并不自动获得上一份失败候选的全部代码/RPC细节。实际提案输入与缺失字段可以在 proposal-feedback-audit 中查证。

## 场景与任务角色

| 任务 | 观察到的主要操作 | 本轮角色 | 评分/解释注意 |
|---|---|---|---|
| general_pickup | 将指定对象抬高，例如 mint-green scissors 10 cm | 部署 smoke、59 案例开发套件、目录辅助消融 | 同一布局重复与新布局分开；失败格式留分母 |
| classify_objects | 将物体按类别分入三篮 | System 1 参考、System 2 开发/验证、独立最终、诊断 | 类别/入篮/高度/夹爪状态等共同决定分段评分；成功还涉及原生完成条件 |
| classify_objects_by_language | 按语言约束进行分类放置 | System 1 参考、独立固定策略迁移、针对性计时 | 不与普通分类直接混为同一个任务；最终策略不是 Agent |
| stack_bowls | 叠放碗 | 1 smoke + 5 formal | 正式1/5；不能扩展成全部泛化能力 |
| cover_blocks | 按顺序遮盖并按要求揭开积木 | 1 smoke + 5 formal | 末帧露出积木可能符合任务流程；不能仅看末帧判失败 |
| insert_tubes | 抓取并插入试管/管件 | 1 smoke + 5 formal | 正式4/5；不能代表全部精细操作任务 |

公开任务配置、实际任务 Python 和原生 reward 定义均保存在无损文本证据库；可以按原始文件路径提取。图像见 `media/scene_atlas.jpg`，具体案例以 `media/scene_manifest.csv` 为准。

### 布局号、case index 与目录数字

- `layout_id` 是任务布局标识，`case_index` 是某批次中的顺序。比如参考分类 Agent 的 case1 对应 layout6，不是 layout1。
- `arx_x5/0/<task>_<layout>.json` 中前面的 `0` 属于该数据路径的评估组/seed 组织，不能拿 layout6 拼成 `arx_x5/6/`。本包所选公共场景从实际使用的0组读取。
- 独立最终布局由生成/冻结流程产生，主要身份是布局 SHA256，不能仅用 case00 与公开 layout0 混淆。
- 不同日期导航可能指向同一批原始数据，不表示多执行了一次。

## 核心表格的字段

| 字段 | 含义 | 禁止的混用 |
|---|---|---|
| episodes/evaluations | 当前分组协议的案例分母 | 不等于全部 HTTP 数 |
| native_complete/native_completed | 原生评估是否正常形成结果 | 失败/0分也是已完成；异常中止不自动补0 |
| success | 原生任务成功布尔值 | 不用局部移动、程序返回、HTTP200替代 |
| partial_score | 原生部分得分，常归一到0–1 | 个别原始汇总 `score` 可能是百分制，先看schema |
| logical_model_calls | 逻辑高层规划次数 | 一次可有多个 transport attempts |
| http_attempts | 实际请求次数 | 不用 action segments 替代 |
| input/prompt_tokens | 供应商报告输入 | 已含 cached input；图像子项不再加一次 |
| cached_input_tokens | 输入中的缓存子集 | 不再加到total；不等于免费 |
| output/completion_tokens | 输出，可能含reasoning | reasoning子集不再次相加 |
| uncached metric | input − cached + output | 不是账单、FLOPs或纯推理时间 |
| control_steps | 已执行原生控制步 | 可以包含保持动作；不是抓取尝试数 |
| completed_primitive_action_steps | 已完整返回 primitive 的动作步 | 不包含未完成 primitive；不等于episode总步 |
| reset_to_result | episode reset到结果的单调时钟差 | 不等于纯物理时间或完整进程wrapper |
| wrapper/batch time | 启动、运行、等待/清理等指定外层范围 | 批次共享值不能每例再加一次 |
| unknown/null/空白 | 未提供或未自然形成的数据 | 不能默认补成0 |

源表保留原字段，便于复核。衍生表的名称和轴标签也保留统计定义。CSV 使用 UTF-8 BOM 以便中文 Windows Excel 打开；JSON 用于保持 null/布尔/嵌套结构。

## 使用无损原始证据库

`sources/all_text_records.jsonl.gz` 按内容 SHA256 去重保存原文本，`sources/ALL_TEXT_INDEX.csv` 将每一个原云端路径映射到内容。多个路径相同内容只保存一份，不删除任何科学字节，也不表示这些副本都是独立运行。

不依赖原仓库即可查找：

```bash
python tools/read_evidence.py 'proposal-feedback-audit.json'
python tools/read_evidence.py '/31_system2_final_validation_20261030T121000Z/workspace/rounds/round-000000/candidate/code/classify_objects.py' --extract candidate_round2.py
```

第二条必须唯一命中；提取时自动校验 SHA256。若只需读主结论，直接打开 `sources/` 下短路径的报告和 CSV，无需解开全部记录。

未打包所有逐帧 PNG、NPY/NPZ、模型权重、环境和全部视频。已选视频为原始 MP4，关键帧另存无修改 PNG；视频不是生成示意图。完整读取底稿和云端原件仍保留，汇报包内索引不冒充完整运行镜像。

## 推荐复核顺序

1. 看冻结协议/模型配置，确认版本、任务、步数、API。
2. 看逐例 native result 和实际 usage，而非只读中文总结。
3. 用 `python tools/recompute_metrics.py` 复算主表；它不发请求、不启动仿真。
4. 看 System 2 candidate、selection、feedback audit 与最终策略绑定，辨认生成、验证和采用是三件事。
5. 看视频清单和关键帧，核对 task/layout/policy/time，并回到原生评分。
6. 看归档 SHA 和索引；目录整理/复制完成与科学实验完成分开证明。
