## 二 两个系统的语言决策与技能执行

本部分建立解释成本差异所需的最小架构背景。

| 维度 | 项目 A 公开路线 | PhysicalRSI 本次实测路线 |
|---|---|---|
| 语言模型工作 | 短动作生成及检查纠正 | 高层技能选择与组织 |
| 后续执行 | 持续语言环路或 VLA 混合路线 | 本地 code 或 VLA 技能 |
| 上下文 | 持久会话与历史引用 | 指令 观测 状态和技能目录 |
| 改进研究 | 按官方公开资料解释 | System 2 生成 验证和选择 |

System 1 执行当前任务；Agent 负责高层路由，pi05、sparse-memory 和代码技能负责执行。System 2 尝试修改执行办法，再依据验证选择版本。Agent 不是第四套机器人权重，thinking 是模型调用模式，与 System 2 改进流程分别定义。

RoboDojo 提供任务、布局和原生评分；Isaac Sim 提供物理与相机；CuRobo 提供运动规划。本地 VLA、规划和仿真消耗计算资源，即使远端语言 API Token 为零，这些成本仍存在。

提出两个待证机制：高层较低频决策可能减少远端调用；目录投影可能减少单次输入。本地执行和技能构建投入另行考虑。建议使用图 09，对应 C02、C06。

## 四 对应任务的在线 Token 差异

普通分类和语言分类使用对应任务记录，主表同时呈现成本与成功分母。B 每个任务有五例 Agent 参考，两种 A 模式共享对应 B 组，不将 B 重复累计为二十例。

| 任务与 A 模式 | A 除以 B 总 Token | A 除以 B 未缓存指标 | A 成功及可评分数 | B 成功及回合数 |
|---|---:|---:|---:|---:|
| 普通分类 mix | 888.07 | 38.04 | 3/5 | 1/5 |
| 普通分类 gpt | 1817.37 | 51.06 | 5/5 | 1/5 |
| 语言分类 mix | 1169.58 | 27.59 | 1/5 | 1/5 |
| 语言分类 gpt | 3049.81 | 75.88 | 2/4 | 1/5 |

语言分类 gpt 有五次尝试，其中四次可评分、两次成功，成本均值包含五次尝试。未缓存指标为未缓存输入加输出，不是人民币费用或 FLOPs。

A 对应组缓存输入约占输入的 97% 至 98%。总 Token 与剔除缓存输入后的指标呈现不同数量级。模型、tokenizer、布局和成功率差异仍未排除，不能写成同等效果下节省 888 至 3050 倍费用。

本部分结论是对应记录中 PhysicalRSI 在线语言 Token 明显较少，数值属于有条件的描述性比较。建议使用图 01 和图 14，在页面保留成功率及条件限制。对应 C05、C23。

## 五 低 Token 的机制证据

### 高层调用与本地执行

正式分类 Agent 每回合核验到一次实际高层 HTTP，后续大量动作由本地技能执行。源码和原生轨迹支持该层级划分。CPU 简化控制表明，高层只绑定一次时，本地闭环仍可承担反馈。

A 的 action segments 未被证明等于 HTTP 次数；CPU 代理不是机器人能力结果。因此，当前不能把跨项目全部差距定量归因于调用次数。

### 技能目录与单次请求

| 对照实验 | 设计 | 输入 Token 降幅 | 关键限制 |
|---|---|---:|---|
| API120 | 20 合成图 两条件 三重复 | 67.31% | 无机器人执行 |
| 原生目录消融 | 两条件各 15 次尝试 | 80.20% | 成功为 5/15 与 6/15 |

API120 总 Token 下降 66.87%，平均 HTTP 时间下降 31.65%。120 调用对应二十个设计输入，不是 120 个独立场景。缓存和时段影响未被单独因果隔离。

原生目录消融三十个逻辑案例中，二十九个获得有效原生结果，一个计划契约失败保留在尝试分母。目录投影也改变展示的能力内容，不能视为只改变无语义字符串长度。

本部分支持决策粒度和请求内容两条机制。67.31% 与 80.20% 属不同自身实验，均不是跨项目节省比例。建议展示图 12、13 或 16，API80 和 CPU 全表放附录。对应 C06、C15、C19 至 C21、C27。

## 十 阶段结论与下一轮研究

| 已测事实 | 有证据支持的解释 | 仍然未知 |
|---|---|---|
| 在线 Token 差距明显 | 决策和本地技能分工不同 | 等质量效率差距 |
| 目录精简减少输入 | 请求内容是成本来源之一 | 跨项目因素定量贡献 |
| API 占部分墙钟 | 本地执行限制整体收益 | 跨项目完整墙钟倍数 |
| 两轮 System 2 无提升 | 执行和反馈存在具体缺口 | 修订后的独立任务收益 |

以下干预尚未开展，按处理变量、固定条件和验收指标提出。

### 动作执行契约

改变 schema、执行确认、终止及异常返回。保持候选、初态、任务和控制频率一致，先过 CPU 契约检查，再在开发集记录动作完成、到位误差和错误回传。

### 候选获得的反馈

对照原输入与增加当前代码、前次候选、结构化 RPC 失败反馈。保持模型、预算、父策略、布局和选择规则，记录有效候选率、得分、成功、异常和 Token，平分保留父策略。

### 规划到抓取链

分别测试高度、用臂和姿态，保持起点、目标和碰撞条件。逐级检查路径、到位、夹持、抬升、保持、入篮和完整任务，不能用 planner pass 代替任务收益。

### Memory 读写闭环

保持核心程序和场景序列，检查写入后可读取、回传、episode 隔离、异常不污染和快照恢复。不将不同 VLA 权重当作纯 memory 开关对照。

### 独立布局小样本验收

候选过契约与开发门禁后，冻结父候选，在两任务各五个新布局配对 pilot。预定顺序和评分，不重跑挑最好，同时报告成功、部分分、异常、成本和各范围时间。详细方案在 next-experiments-preregister-draft.csv，证据 C17。
