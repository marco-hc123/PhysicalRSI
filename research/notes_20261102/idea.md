# PhysicalRSI：有限范围复现、Token 与运行时间研究

档案性质：已完成阶段的事实归档。用户于 2026-11-01 确认沿用现有研究范围；下一阶段实验另在 Discussion 中确定。所有结果统一从实验室服务器现有研究目录访问。

## 1. 核心概述

- **一句话总结 (One-Sentence Summary):** 在有限机器人仿真任务中复现 PhysicalRSI 的技能执行与自改进工作流，核对任务表现、语言接口 Token 和执行时间，并解释已有证据能够支持及不能支持的差异。
- **一段话摘要:** 已有阶段完成软件与依赖检查、合成输入 API 计量、原生技能/Agent 评估、System 2 提案与选择、独立验收及失败机制诊断。档案把这些结果按实验对象和统计分母分别保存。System 2 两轮未观察到验证得分提升；该负结果与成功案例、失败尝试一起保留。跨项目 Token 对比是条件性描述，完整墙钟差异和同等任务质量下的因果收益尚未建立。

## 2. 背景、动机与目标

### 2.1 背景与动机
PhysicalRSI 将任务、技能、运行时记忆与候选评估组合起来。仅看到接口能够运行，不能推出机器人任务成功；看到 Token 较少，也不能直接推出同等质量下更便宜或更快。因此需要将执行、成本与改进证据逐项对应。

### 2.2 既有比较范围
- 研究主体：PhysicalRSI 的固定策略、代码技能和高层 Agent 路线。
- 既有公开参照：GPT-as-Policy 的固定公开快照；本阶段没有重新运行该项目。
- 证据缺口：不同项目模型、tokenizer、场景、成功率与计时边界不同，尚无同条件因果比较。本档案不提出新的 SOTA 声明。

### 2.3 研究目标
1. 如实呈现有限范围复现的完成程度、任务结果与失败记录。
2. 分别核对供应商 API usage、合成输入计量和原生任务成本。
3. 记录 System 2 候选生成、验证、选择及恢复证据，区分自动提案与人工诊断修复。
4. 从已知限制中形成下一阶段可验证问题；具体干预、预算和终止条件尚未立项。

## 3. 技术实现概览

- **System 1:** 根据任务与观测选择既有技能，由 code/VLA 等本地执行路径产生控制。
- **System 2:** 产生候选，在开发/验证记录中比较父策略与候选，按记录中的选择规则决定保留项。
- **已有路线:** pi05、pi05-sparse-memory、固定 code、高层 Agent。两种 VLA 的差异并非纯粹的 memory 开关。
- **方法与版本:** 见 [method.md](method.md)、原始协议和 [实验索引](history/experiment_index.csv)。实验室 source-pins 记录主源码 `90b322a3a362aad14125f36d8ed080ca31daaea6`；各阶段补丁/快照必须按各自协议核对，不能套用同一个版本号。

## 4. 历史实验设计与评价口径

### 4.1 数据与任务
合成输入 API 批次与原生机器人批次独立统计。120 次 API 批次为 20 个合成场景 × 2 个目录条件 × 3 次重复；原生参考矩阵为 2 个分类任务 × 4 条路线 × 5 个布局。其他抓取、扩展任务、诊断及失败批次从 HISTORY 的完整目录入口查阅。

### 4.2 已完成流程
环境/软件检查 → 合成输入计量 → 原生技能与 Agent 验证 → 协议固定 → System 2 候选验证与选择 → 独立验收 → 机制诊断。此顺序描述历史阶段，不是本次新运行计划。

### 4.3 评价指标
- **Primary:** 按任务、路线、队列分别报告原生成功数及明确的分母，同时报告原生评分、规划失败、未完成和异常。不同队列及评估对象不合并；具体分母遵循对应历史协议。
- **Secondary:** 供应商 input/output/total Token、缓存输入子集、HTTP 次数与延迟、控制步数，以及有明确起止边界的运行时间。
- **System 2:** 对照父策略与候选的验证表现及选择结果；接口完成不等于能力提升。
- **限制:** API 合成场景不是机器人评估；Token 不是费用账单；不同计时边界不能相除得到跨项目加速。

## 5. 已有结果与贡献边界

- 120 次合成输入 API：输入均值下降约 67.31%，总 Token 均值下降约 66.87%，HTTP 均时下降约 31.65%；这不是机器人成功率或整体墙钟结论。
- 原生分类参考矩阵：每格 n=5。固定 code 两任务分别为 2/5、1/5；Agent 为 1/5、1/5；两种 VLA 各任务均为 0/5。
- System 2 两轮：父策略与候选验证得分均为 0，两轮均保留父 pi05，未测得提升。
- 独立最终验收：保留的 pi05 在两任务各 0/10；评估对象为该策略，不是完整 Agent。
- 阶段贡献是可追溯的有限复现、计量分解和负结果诊断；新增算法、完整榜单复现与同条件效率优势尚未得到验证。

## 7. 人话版 (ELI5)

- **同步戳 (Sync stamp):** `source-hash: 02f47c6f0986` · 更新于 `2026-11-01`

### 7.1 承重的一句话
我们在查清：这套机器人系统实际能做成哪些任务，调用语言模型花了多少资源，以及它尝试修改自己后有没有真的变好。

### 7.2 现实中的问题
机器人可能收到了一份格式正确的计划，却没把物体拿起来；也可能语言模型调用很少，但机器人仍花很久才结束。必须把“计划生成了”“动作执行了”“任务完成了”分别核对。

### 7.3 当前方式与不足
系统可以挑选现成的动作技能，也能提出修改方案后做比较。目前有限实验已走通这些步骤，但两轮自改进比较都没有得到更高验证分数。

### 7.4 一个具体类比
像厨师先从菜谱中选一种做法，再完成许多操作。语言模型类似负责选菜谱的人，机器人策略负责具体操作。少问几次选菜谱的人，可以减少这部分沟通，但菜是否做成、总共用了多久，还要单独测量。

### 7.5 类比在哪断
机器人面对的是视觉、动作和物理约束，菜谱写得清楚不保证抓取能实现。更换整套执行策略也不等于只增加一本笔记，因此不能把所有差异都归因于“记忆更好”。

### 7.7 怎么算赢、卡在哪里
算赢要看同一任务和评估规则下，完成任务的次数是否更高，或保持任务质量时资源与时间是否更低。现阶段两轮修改尚未提高验证分数；下一步需要从失败证据中选出一个能检验的原因，再确定实验，而不是把已有负结果重复包装成成功。
