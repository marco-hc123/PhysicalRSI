# PhysicalRSI 方法与历史计量定义

本文件整理已确认研究范围内的既有执行结构和指标定义，没有新增训练损失、定理或科学假设。原始批次协议与评分器优先。

## 1. 方法定位

System 1 选择并执行现有技能；System 2 提出候选、运行对照验证并选择保留项。既有阶段使用发布策略权重，没有在本阶段重新训练这些权重。人工接口修复、诊断补丁和自主候选分别标注。

执行入口对应 ../repos/（原始归档位置：`../repos/`） 的项目与快照，过程脚本在 ../experiments/（原始归档位置：`../experiments/`），记录在 ../result/（原始归档位置：`../result/`）。记录目录 `code/` 不承载另一个重复代码库。

## 2. 形式化与统计口径

### 2.1 任务表现
对确定的任务、路线、队列与协议，成功比例为 $S=k/N$。其中 $k$ 为按原生评分规则成功的案例数，$N$ 必须注明是全部计划案例还是完成原生执行的案例。规划失败、异常和未完成单列；不能通过丢弃失败改变分母。原生部分得分按协议另报。

### 2.2 语言接口资源
同一供应商定义下，$U_{total}=U_{input}+U_{output}$。缓存输入和 reasoning 字段若属于上述项的子集，不重复相加。逻辑任务、逻辑规划和实际 HTTP 请求分别计数；没有 usage 的记录标为未知。

两个同类条件的输入均值下降率为 $R=1-\bar U_{projected}/\bar U_{unprojected}$。120 次批次按每条件 60 次调用统计，同时保留同场景重复的配对信息；费用与算法因果效应不由这个比值自动推出。

### 2.3 时间
HTTP 时间、技能控制时间、reset-to-result 时间、wrapper 时间与完整墙钟各保留边界。没有完整起止证据时记为未知。持续进程和冷启动的小样本结果只描述实际测试条件。

### 2.4 自改进评价
验证变化可记为 $\Delta Q=Q_{candidate}-Q_{parent}$，同时记录实际选择器的决定。已完成两轮的父策略与候选验证评分均为零，两轮选择 `retain_parent`。本表达式是历史指标说明，不替换既有选择器或增加训练目标。

## 3. 已观察结论

1. 120 次合成输入条件比较降低了语言输入与总 Token，并观察到较低 HTTP 均时；该批次没有执行机器人动作。
2. 原生参考矩阵的每个任务/路线仅 5 个布局，不能据此宣称普遍优劣。
3. 两种 VLA 的训练与结构不同，不能作为纯记忆开关消融。
4. System 2 未观察到验证得分提升；独立最终验收评估保留的 pi05，两任务各 0/10。
5. 当前没有形式化性能保证；理论证明和同条件因果效应未由此阶段建立。

## 4. 机制解释及局限

高层选择技能后由本地执行大量控制，可以解释语言决策粒度与接口账目的差异。但模型、任务质量、tokenizer、场景、缓存与执行路径均可能不同，未隔离各因素贡献。失败诊断提示判断边界、规划可行性、控制约束、类别映射和反馈回传等问题；修复局部问题尚不等于任务闭环成功。
